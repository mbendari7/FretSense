# Feedback: spec 001 Phase 12 (T101-T110, accessibility convergence), Mode B, 2026-11-27

Tested against the running dev server at http://localhost:5173 with throwaway Playwright (Chromium) scripts kept outside the repo. No source, test or spec was edited. Hand to the product-owner subagent to triage.

## Summary
- Overall: 4 of 5 stars. The dialogs, linked form errors and large-text neck are clearly better, and I found no overlap or horizontal page overflow. Two real keyboard gaps remain: an invisible focus ring on selected orange buttons, and lost focus after "Clear progress".
- Top 3 problems:
  1. The focus ring is invisible on the selected Root button on Explore (F-1).
  2. After confirming "Clear progress" focus drops to the page body and nothing is announced (F-2).
  3. The drill-setup note-set radios are stacked and centred (radio above label above hint) and look broken next to the inline Octave radios (F-3).
- What worked well:
  - Explore at Large text: 0 overlapping labels on the 6-string guitar (1280 and 390 px) and the 5-string bass (BEADG, 1280 and 390 px). Marker labels render at 24 px.
  - The neck scrolls on 390 px and "Jump to frets" moves it (scrollLeft 0, 232, 442, back to 0).
  - The revealed-answer label after a wrong answer is readable. It is cream text (239,233,220) on the board shade with a 28% blue tint. By my own arithmetic that is about 5.8:1; I did not run a contrast tool. The reveal also uses a dotted ring and the text "E on string 5 is at fret 7", so it does not depend on colour.
  - The wrong-answer marker is a pink square with an X, so it is distinguishable by shape.
  - Dialogs (import preview, reset, instrument editor): `role=dialog`, `aria-modal=true`, focus goes to the heading, Tab and Shift+Tab stay inside, Escape closes, and focus returns to the opener.
  - Form errors: the field gets `aria-invalid=true` and `aria-describedby` pointing at a `role=alert` message that names the string ("String 4: "H9" isn't a note like E2 or F#1."). Drill setup does the same for Questions (count 3) and for no strings selected.
  - Top-bar focus ring is amber on dark and clearly visible. Paper focus ring is dark amber `rgb(138,75,0)`, 3 px, offset 2.

## Steps I actually ran
1. Fresh context, picked "Standard (EADGBE)", opened Settings. Text size, Theme and the other controls are `role=radio` buttons with `aria-checked`. Set Large and Light.
2. Explore at 1280 and 390 px, with Light theme and again with Dark theme at 1280. I counted overlapping SVG text boxes: 0 in all cases. Label sizes were 19 and 24 px. I took screenshots at 1280 and 390 px, and zoomed to fret 10. Checked the neck scroll container and the jump buttons.
3. Note-finding drill at Large in Light and Dark themes. Tapped the wrong string (hint "That's string 4. This question is on string 6.") and the right string with the wrong fret (reveal, with Continue). Read the computed colours of the revealed label.
4. Tabbed through Explore at 1280 px and logged tag, name and outline for 45 stops. The neck is a single roving stop (arrow keys move, Enter selects, with a visible amber square). Screenshotted the neck focus. Checked the focus-visible and outline colours of the selected Root C.
5. My Gear, "Custom instrument": opened it at 1280 and 390 px, tabbed 30 times (stays in the dialog), entered "H9" for String 4 and submitted, then pressed Escape (focus returned to the opener). On the other run I corrected it to "D3" and added the instrument.
6. Drill setup: Questions 3 (linked error, Start disabled), all strings off (error on the fieldset), from 15 to 3 (no error), narrow ranges (no error). Measured note-set row sizes and screenshotted them at 1280 and 390 px.
7. Answered 3 drill questions, ended the drill, opened Progress. Exported the JSON, imported a deliberately truncated file ("The file is not valid JSON."), imported the real file (dialog "Restore from file", Escape returns focus to "Import a file"), then Clear progress (the focus finding F-2).
8. 5-string bass (BEADG) Explore at Large, 1280 and 390 px: no overlaps.
